# Пошагово

**Демо:** https://deboshirx.ru/poshagovo/ (вход: `artem@poshagovo.ru` / `demo1234`)

Платформа интерактивных пошаговых инструкций с чек-листами. Автор пишет инструкцию («как собрать ПК», «как получить справку в деканате», «как поставить Docker»), а читатель не просто читает её, а **проходит**: отмечает пункты, переходит дальше, видит прогресс. Если застрял — жмёт «Застрял» и задаёт вопрос прямо к этому шагу. Автор в аналитике видит, на каком шаге люди спотыкаются и бросают.

## Зачем

Инструкции для повторяющихся задач обычно разбросаны по форумам и видео, в них нет порядка, легко пропустить шаг, а автор никогда не узнаёт, где у читателей возникли проблемы. Здесь у инструкции есть структура (шаги + чек-листы), а у автора — обратная связь в цифрах.

## Что умеет

**Основное**
- Каталог с категориями, сортировкой (полезные / популярные / по оценке / новые / быстрые)
- Прохождение шаг за шагом: прогресс-бар, чек-лист на каждом шаге, карта шагов, навигация стрелками на клавиатуре. Прогресс сохраняется на сервере — можно продолжить с другого устройства
- Личный кабинет автора: создание и редактирование инструкций, черновики, перестановка шагов, предпросмотр

**Сверху**
- Комментарии к шагам трёх типов: комментарий, вопрос, предложение улучшения. Автор отмечает предложения как «учтено»
- «Полезно / не полезно» для каждого шага
- Форк: можно скопировать чужую инструкцию, улучшить и опубликовать. У оригинала появляется блок «Улучшенные версии»
- Роли: ученик и эксперт. Эксперт может поставить инструкции отметку «проверено», его комментарии выделяются. Регистрация эксперта — по коду (`EXPERT_CODE`)
- Умный поиск: понимает разные формы слов, сленг и опечатки (*«докера»*, *«видюха»*, *«лаба»*, *«убунту»*), ищет и по тексту шагов — показывает, в каком шаге нашлось
- Рейтинг полезности: байесовское среднее оценок + доля дошедших до конца, чтобы одна пятёрка не выводила инструкцию в топ
- Аналитика для автора: воронка по шагам, где бросают, медианное время на шаг против запланированного, сколько раз нажимали «Застрял», автоматический поиск «узких мест» с объяснением причин, активность за 2 недели
- Помощник автора: вставляете текст с форума — он разбивается на шаги и чек-листы. Работает на эвристиках, а если задан `ANTHROPIC_API_KEY` — через LLM. Плюс «проверка качества» в редакторе (нет чек-листа, слишком длинный шаг, «и т.д.» и т.п.)
- Экспорт в PDF (версия для печати → «Сохранить как PDF»)
- Встраивание на сторонние сайты через `<iframe>` (`/embed/:id`)
- Офлайн-режим: service worker кэширует приложение и открытые инструкции, события прохождения копятся в очереди и досылаются, когда появится сеть. Гости тоже могут проходить — после регистрации их прогресс привязывается к аккаунту
- Адаптивная вёрстка и тёмная тема (по настройке системы)

## Стек

- **Backend:** Node.js 22+, Express 5, SQLite через встроенный модуль `node:sqlite` (без нативных зависимостей — ничего не нужно компилировать)
- **Frontend:** React 19, React Router 7, Vite. Без UI-библиотек, стили написаны вручную
- Авторизация — токены сессий в БД, пароли через `scrypt`

## Запуск

Нужен Node.js **22.13+** (проверено на 24 LTS).

```bash
npm install
npm run dev
```

Откроется фронтенд на http://localhost:5173 (API на :3001 проксируется). При первом запуске база заполняется демо-данными.

Продакшен-сборка, всё на одном порту:

```bash
npm run build
npm start
```

→ http://localhost:3001

Пересоздать базу с демо-данными: `npm run seed`.

Для деплоя на [Render](https://render.com) в репозитории есть `render.yaml` (New → Blueprint). На бесплатном тарифе диск не сохраняется между перезапусками, поэтому после рестарта база снова заполняется демо-данными.

### Обычный PHP-хостинг (без Node.js)

На большинстве недорогих хостингов Node.js не запустить, поэтому в `php/` лежит PHP-версия API (PHP 7.4+, `pdo_sqlite`). Маршруты и формат ответов те же, что у Express-сервера, фронтенд не меняется.

```bash
./scripts/build-hosting.sh            # соберёт всё в build/hosting
./scripts/build-hosting.sh --publish  # и зальёт в ветку hosting
```

Содержимое `build/hosting` кладётся в корень сайта (Apache с mod_rewrite). Дальше сайт обновляется одной ссылкой `https://сайт/install.php?key=...` — скрипт сам скачает свежую сборку из ветки `hosting` (ключ лежит в файле `install.key` на хостинге). База хранится уровнем выше корня сайта и при обновлении не трогается; `&reset=1` вернёт демо-данные.

По умолчанию сборка рассчитана на подпапку `/poshagovo/` (меняется через `VITE_BASE=/ ./scripts/build-hosting.sh`), база кладётся рядом с корнем сайта, вне `docs`.

## Как считается аналитика

Каждое прохождение (`runs`) хранит текущий и максимальный достигнутый шаг. Клиент шлёт события `enter` / `complete` (с длительностью) / `stuck`. Прохождение считается брошенным, если в нём сутки ничего не происходило.

Для каждого шага: сколько до него дошли, сколько бросили именно на нём, медиана времени, «застрял», голоса. Из этого собирается `problemScore` — взвешенная сумма доли бросивших, доли «застрял», доли дизлайков и превышения запланированного времени. Шаги с высоким баллом показываются как узкие места с человеческим объяснением («здесь бросили 7 из 33 (21%)», «в среднем 19 мин вместо 15»).
